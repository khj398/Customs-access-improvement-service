### 3.1 데이터셋 기초 통계 (→ E01 / 논문 표 3)

수집 JSON 원본 507행 → 복합 PK 기준 중복 10행 제거 → **물품 497건**.

| 항목 | 값 |
|---|---|
| 공매 건수 | 483건 |
| 물품 건수 | 497건 |
| 대상 세관 수 | 4개 |
| 한글 포함 물품명 | 399건 (80.3%) |
| 영문 전용 물품명 | **98건 (19.7%)** |
| 평균 물품명 길이 | 43.0자 (최대 188자) |
| 공매당 평균 물품 라인 수 | 1.03건 (최대 5건) |
| 예정가 범위 | 3,270 ~ 4,631,905,590원 |
| 공매 기간 | 2026-08-25 10:00 ~ 2026-08-27 13:00 |

**수집 출처별 언어 구성** — 서론의 핵심 근거가 되는 표다.

| collector_source | 구분 | 물품 수 | 한글 포함 | 한글 포함률 | 평균 길이 |
|---|---|---|---|---|---|
| BUSINESS | 수입화물 | 107 | 19 | **17.8%** | 27.5자 |
| PERSONAL | 휴대품 | 390 | 380 | 97.4% | 47.2자 |

계획서 E1의 판정 기준은 "수입화물의 한글 포함 비율이 0%에 가깝게 나오면 서론의 주장이 성립"
이었다. 실제는 17.8%로 0%는 아니지만 휴대품(97.4%)과의 대비는 뚜렷하다.

### 3.2 룰 단독 분류 커버리지 (→ E07 (1))

`rules.yaml` 85개 룰을 실제 물품명에 적용한 결과다. DB 쓰기 없이 `match_rule()`만 호출했다.

| 항목 | 값 |
|---|---|
| 룰 매칭 | 259건 |
| 룰 미매칭 (LLM 보완 대상) | 238건 |
| **룰 단독 커버리지** | **52.1%** |
| BUSINESS 커버리지 | 28.0% (30/107) |
| PERSONAL 커버리지 | 58.7% (229/390) |

매칭 상위 룰은 `ko_beauty_skincare`(62) · `ko_beauty_perfume_ko`(48) ·
`ko_beauty_brush_makeup`(38) 순으로, 한글 키워드 룰이 상위를 점유한다.

> 기존 리포트의 "룰 76.3%"는 93건 표본 기준이었다. 현재 497건 기준으로는 52.1%이며,
> 나머지 47.9%를 LLM이 부담한다는 뜻이므로 **E07의 하이브리드 정당화 논거는 오히려 강해진다.**

### 3.3 한글 검색 비교 (→ E03(A) / E08)

부록 A 질의 20개에 대해, (A) LIKE 베이스라인은 실제 MySQL `LIKE '%질의%'`와 동일한
부분문자열 매칭으로 계산했다. 토큰 열은 RAW/SYN/CATEGORY 토큰을 오프라인 재현한 값이다.

| 방식 | 0건 질의 수 | 검색 가능 합계 |
|---|---|---|
| (A) LIKE 베이스라인 (유니패스 동등) | **12 / 20** | — |
| RAW 토큰만 | 20 / 20 | 0 |
| RAW + SYN | 15 / 20 | 15 |
| RAW + SYN + CATEGORY | **11 / 20** | 266 |

계획서의 성립 조건은 "A의 0건이 15개 이상, B의 0건이 3개 이하"였다. **현재 데이터에서는
두 조건 모두 충족되지 않는다.**

### 3.4 영문 전용 물품 부분집합 (논문 주장이 실제로 성립하는 모집단)

같은 질의 20개를 **영문 전용 물품 98건**에만 적용하면 결과가 정반대로 선명해진다.

| 지표 | 값 |
|---|---|
| (A) LIKE 0건 질의 | **20 / 20** |
| (B) 토큰(재현) 0건 질의 | 12 / 20 |
| LIKE로는 0건인데 토큰으로 검색된 질의 | **8개** (화장품·셔츠·신발·가방·완구·향수·캔들·주류) |

즉 "영문 물품명은 한글로 검색할 수 없다 → 토큰으로 가능해졌다"는 주장은
**영문 전용 부분집합에서 100% 성립**한다. 전체 코퍼스로 표를 만들면 휴대품(한글 물품명 97.4%)이
베이스라인 점수를 끌어올려 대비가 사라진다.

### 3.5 동의어 사전 오탐 점검

`synonym_tokens_from_text()`는 `src_term in norm_text` 부분문자열 매칭을 쓴다.
그 결과 2자 이하 엔트리가 무관한 물품명에 매칭된다.

| 오탐 엔트리 | 오탐 건수 | 예시 |
|---|---|---|
| `AR → 증강현실` | 51 | SKIN C**AR**E COSMETIC, HE**AR**T, PREP**AR**ATIONS |
| `AR → 스마트글라스` | 51 | 〃 |
| `PC → PC` | 2 | TOTAL **PC**S ACTION CAMERA |
| `JU → 주` | 1 | **JU**JUBE WITH WALNUT |

**전체 물품의 10.9%(54/497)가 잘못된 검색 토큰을 갖고 있다.**

## 4. 발견 사항과 논문에 미치는 영향

### F-1. 서론의 전제가 현재 데이터와 어긋난다 — 영향 큼

논문 1장은 "물품명이 영문/약어 위주라 검색 장벽이 크다"를 문제로 삼는다.
그러나 현재 수집 데이터의 **80.3%는 한글 물품명**이다(휴대품 비중 78%).

- **권고**: 문제 정의를 "수입화물 공매 물품(전체의 21.5%)은 물품명이 영문 전용이어서
  한글 검색이 원천적으로 불가능하다"로 좁힌다. 표 3에 출처별 언어 구성표(3.1)를 넣으면
  이 범위 한정이 자연스럽고, 오히려 데이터를 파악하고 있다는 근거가 된다.
- 반대로 범위를 좁히지 않으면, 심사에서 "휴대품은 이미 한글인데 무엇을 개선했나"라는
  질문에 답할 수 없다.

### F-2. 부록 A 질의셋이 현재 데이터와 맞지 않는다 — 영향 큼

와인·배터리·냉장고·타이어·러닝머신·헤드폰·케이블·펌프·접시·식기 등은 **데이터에 존재하지 않는다**.
계획서 부록 A는 "A·B 양쪽 모두 0건인 질의가 5개를 넘으면 질의셋을 재선정한다"고 규정했는데,
현재 그 조건에 명확히 해당한다(전체 코퍼스 기준 11개가 양쪽 0건).

- **권고**: 질의셋을 데이터 기반으로 재선정한다. 오프라인 분석이
  **LIKE 0건 + 토큰 검색 성공 후보 28개**를 이미 뽑아 두었다
  (`results/OFFLINE/query_candidates.csv`). 상위: 스킨케어(93) · 색조화장(43) · 상의·하의(20) ·
  스포츠·레저(12) · 헤어케어(4) · 아이스크림(4) · 캔들(3).
- **주의**: 결과가 잘 나오는 질의만 고르면 체리피킹이다. 선정 기준
  (예: 12개 대분류에 고르게 분포 + 데이터 내 해당 물품 3건 이상 + 실사용자가 입력할 법한 일반명사)을
  4.3절에 명시하고, 기존 부록 A 질의도 0건 결과 그대로 함께 보고하는 편이 안전하다.

### F-3. 동의어 사전 `AR` 오탐 — 실험 전 수정 권고

물품의 10.9%에 "증강현실 / 스마트글라스" 토큰이 잘못 붙는다. E03의 P@5를 직접 떨어뜨린다.

- **수정안**: `synonym_tokens_from_text()`에서 `len(src_term) < 3`이면 부분문자열 매칭을 막고
  `raw_tokens` 정확 일치만 허용한다. 한 줄 조건 추가로 해결된다.
- 이 수정을 **E03·E08 실행 전에** 반영해야 한다. 실행 후 고치면 두 실험을 다시 해야 한다.

### F-4. 스키마의 `KO` 토큰 유형이 실제로는 생성되지 않는다

`item_search_token.token_type`은 `RAW / KO / SYN / CATEGORY` 4종을 정의하지만,
`build_classification.py`는 `KO`를 한 번도 쓰지 않는다(코드 전수 확인).
실제 생성 유형은 **RAW / SYN / CATEGORY 3종**이다.

- **권고**: 논문 3.4절과 그림 3을 3종 기준으로 서술한다. E08도 3단계 누적으로 보고한다
  (스크립트는 4단계로 집계하되 KO는 항상 0으로 나오므로 결과 해석에 지장 없음).

### F-5. 룰 커버리지가 기존 리포트보다 크게 낮다 — 유리한 발견

93건 표본 기준 76.3% → 497건 기준 **52.1%**. 특히 BUSINESS는 28.0%.

- **권고**: E07의 결론 문장을 "룰 단독 52.1% → 하이브리드 N%"로 쓰면
  LLM 결합의 필요성이 훨씬 강하게 정당화된다. 낮은 수치를 감출 이유가 없다.

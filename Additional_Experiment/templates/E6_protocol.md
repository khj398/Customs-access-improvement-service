# E06 사용성 과업 비교 실험 — 진행 스크립트

실험계획서 6장 E6 / 부록 B-3 기준. 진행자는 이 문서를 그대로 읽고 따라간다.

## 1. 준비 (실험 전날)

| 항목 | 내용 |
|---|---|
| 참가자 | 세관 공매 경험이 없는 일반 사용자 8~10명 (동기·지인) |
| 식별 | 익명 번호 P1~P10 만 부여. 이름·연락처·소속 등 개인정보는 기록하지 않는다 |
| 기기 | 참가자 전원 동일 기기·동일 화면 크기 사용 (기기 차이가 시간에 섞이지 않게) |
| 환경 | 제안 서비스: cais_back(3000) + Meilisearch(7700) + Flutter 앱 구동 확인 |
| 환경 | 유니패스: 공매 물품 조회 화면을 미리 띄워 둔 상태에서 시작 |
| 도구 | 스톱워치, 인쇄한 기록지(`E6_usability_record.csv`), 만족도지(`E6_satisfaction.csv`) |
| 순서 | 홀수 참가자는 U→C(유니패스 먼저), 짝수 참가자는 C→U(제안 서비스 먼저) |

화면 녹화는 하지 않는다. 스톱워치와 기록지만으로 충분하다.

## 2. 안내문 (참가자에게 그대로 읽는다)

> 오늘은 두 개의 웹/앱 서비스에서 같은 과제를 수행해 주시면 됩니다.
> 두 서비스 모두 세관에서 공매로 나온 물건을 찾아보는 서비스입니다.
> 정답을 맞히는 시험이 아니라 **서비스가 얼마나 찾기 쉬운지**를 보는 것이므로,
> 잘 안 되면 그것 자체가 결과입니다. 편하게 하시면 됩니다.
> 각 과제는 최대 3분이며, 3분이 지나면 제가 중단시킵니다.
> 진행 중에는 제가 힌트를 드릴 수 없습니다.

**금지 사항(진행자)**
- 어느 쪽이 우리가 만든 서비스인지 미리 알리지 않는다. ("A 서비스", "B 서비스"로만 부른다)
- 조작 힌트를 주지 않는다. 참가자가 물어도 "편하신 대로 해보세요"로만 답한다.
- 참가자의 조작을 평가하는 말(잘하셨어요/그건 아니에요)을 하지 않는다.

## 3. 과업 목록

| 과업 | 지시문 (그대로 읽는다) | 성공 기준 | 확인 포인트 |
|---|---|---|---|
| T1 | "와인과 관련된 공매 물품을 찾아서, 그 물품의 예정가가 얼마인지 말씀해 주세요." | 와인류 물품 1건의 예정가를 말함 | 한글 검색 성립 여부 |
| T2 | "주방에서 쓰는 식기류에 해당하는 물품을 3건 찾아 주세요." | 식기류 3건 제시 | 카테고리 탐색 |
| T3 | "OO세관에서 진행 중인 공매 물품을 찾아 주세요." (세관명은 사전에 하나로 고정) | 해당 세관 물품 1건 제시 | 필터 기능 |
| T4 | "마음에 드는 물품을 저장해 두고, 그 물품의 마감 일정을 확인해 주세요." | 저장 + 마감일 확인 | 유니패스는 수행 불가 → 실패로 기록 |

T3의 세관명은 모든 참가자에게 동일한 값을 사용한다(예: 인천세관). 실험 전에 해당 세관에 실제로
진행 중인 물품이 있는지 확인해 둔다.

## 4. 진행 절차 (참가자 1인 기준, 약 20분)

1. 안내문을 읽는다. 질문을 받는다.
2. 첫 번째 서비스를 연다(순서표에 따라 유니패스 또는 제안 서비스).
3. T1 지시문을 읽고 **동시에 스톱워치 시작**.
4. 참가자가 "찾았습니다"라고 말하고 답을 말하면 정지. 시간과 성공 여부(O/X) 기록.
5. 180초가 지나면 "여기까지 하겠습니다"라고 중단. **시간은 180으로, 성공은 X로 기록**.
6. T2 → T3 → T4 를 같은 방식으로 반복한다.
7. 두 번째 서비스로 바꿔 T1~T4를 반복한다.
8. 종료 후 만족도지를 준다: "각 서비스가 물건을 찾기에 얼마나 편했는지 1~5점으로 표시해 주세요."
   (1=매우 불편, 5=매우 편함)

## 5. 기록 규칙

- 시간은 초 단위 정수로 기록한다.
- 성공/실패는 `O` / `X` 로만 기록한다.
- 180초 초과 중단 건은 시간 180, 성공 X.
- T4의 유니패스 열은 처음부터 `180 / X`로 채워져 있다(기능 부재로 수행 불가).
- 특이사항(참가자가 검색어를 영어로 입력했다 등)은 note 열에 짧게 남긴다. 논문 4.4절 서술 재료가 된다.

## 6. 집계

기록지를 `Additional_Experiment/results/E06/usability_record.csv` 로 저장한 뒤:

```bash
python Additional_Experiment/scripts/e06_usability_analyze.py
```

빈 기록지를 만들려면:

```bash
python Additional_Experiment/scripts/e06_usability_analyze.py --init
```

## 7. 논문 기술 시 주의

- 참가자 수가 적으므로(8~10명) "통계적으로 유의하다"는 표현은 쓰지 않는다.
  평균 완료 시간과 성공률을 그대로 제시하고, 표본 규모의 한계를 한 문장으로 밝힌다.
- 참가자는 세관 공매 비경험자이므로 "일반 사용자 기준의 초기 접근성"으로 범위를 한정해 서술한다.
- T4는 기능 부재로 인한 수행 불가이므로, 시간 비교가 아니라 기능 유무 비교로 해석한다.
